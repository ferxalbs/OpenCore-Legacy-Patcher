Si Tahoe falla, recupera primero el acceso a Sequoia

Guía específica para el equipo ASUS de Fer y su configuración probada. El objetivo es recuperar el arranque y conservar los archivos antes de considerar una reinstalación.

Ruta rápida: conectar el USB de 31 GB → menú de arranque ASUS → USB UEFI → OpenCore → macOS → Enter normal. Esa entrada corresponde al Sequoia existente. No necesitas reinstalarlo si todavía arranca.

2. Tahoe no abre: vuelve al Sequoia existente

  1. Conserva conectado el USB de 31 GB. Si el equipo responde, reinicia normalmente. Si está completamente bloqueado, fotografía el error antes de forzar el apagado; no interrumpas una instalación que aún progresa.
  2. Abre el menú de arranque ASUS. En muchas placas se accede con F8; dentro de la interfaz UEFI también puede aparecer «Boot Menu» o «Boot Override». Selecciona el USB de 31 GB en modo UEFI, como en los arranques que ya funcionaron.
  3. Cuando aparezca OpenCore, elige macOS con Enter normal. No elijas «Tahoe-Pruebas», «macOS Installer» ni «Install macOS Sequoia» para esta vuelta al sistema existente.
  4. Si una entrada está oculta, pulsa espacio para mostrar las auxiliares. No elijas «Reset NVRAM» como prueba general.
  5. Desde Sequoia, copia primero los documentos recientes de Tahoe-Pruebas - Data/Users/fer a una ubicación externa. No fuerces permisos ni desbloqueos si el volumen está cifrado o no se deja leer.
  6. Conserva la versión y el texto del fallo. Un error de audio no requiere borrar Tahoe; un fallo de arranque tampoco demuestra que los datos estén dañados.

Control conocido en Sequoia: la GT 730 debe cargar com.apple.GeForce y completar la prueba Metal. En este proyecto se reparó una pérdida de aceleración restaurando el GeForce.kext que faltaba. No repitas esa reparación si el archivo y la aceleración siguen bien.

3. Solo falla el Wi-Fi o el audio de Tahoe

La configuración nativa está limitada a Darwin 25. Sequoia conserva sus controladores anteriores. El perfil de referencia usa AirportItlwm Tahoe 2.4.0 alpha, AppleALC 1.9.8 y SimpleHDA 1.0.0. El layout inyectado correcto para este equipo es 13.

  1. Si Tahoe abre, ejecuta el diagnóstico de 03-Instaladores-y-Utilidades/Tahoe-Pruebas/Comprobar-WiFi-Audio-Nativo.command. Es de lectura y muestra controladores, interfaces, estado de SimpleHDA y dispositivos de audio.
  2. No vuelvas a cargar simultáneamente itlwm y AirportItlwm. Si HeliPort se abre con el perfil nativo, ciérralo.
  3. Si necesitas deshacer los servicios nativos, vuelve a Sequoia. En la instalación original existe el comando Revertir-WiFi-Audio-Nativo-Tahoe.command dentro del directorio privado de auditoría de Tahoe. Solo funciona mientras conserve sus rutas y respaldos originales.
  4. Si las rutas originales ya no existen, el kit incluye 07-Recuperacion-Portable/Restaurar-Config-Anterior.command. Restaura únicamente el config previo a los servicios nativos en el USB de arranque identificado. Deja intactos los parches gráficos de Tahoe. El Wi-Fi de Tahoe vuelve al perfil itlwm/HeliPort y el audio nativo deja de estar habilitado.
No reviertas los parches gráficos para arreglar solo el sonido o la red. El snapshot sellado original de Tahoe no tiene aceleración Kepler y fue el estado que mostró pantalla negra con cursor. Volver a él no garantiza una interfaz utilizable.

4. Se dañó la EFI del USB o no aparece OpenCore

El respaldo 01-EFI-Actual/EFI contiene la EFI que funcionó con ambos sistemas. No contiene una imagen completa del disco interno.

Si todavía puedes entrar en Sequoia

  1. Conecta MATE y el USB de 31 GB.
  2. Abre 07-Recuperacion-Portable/Restaurar-EFI-Probada.command. Comprueba sus mensajes antes de introducir la contraseña local.
  3. El comando verifica el respaldo, identifica el USB por UUID y tamaño, conserva una copia de su EFI previa en MATE y copia el perfil probado. No selecciona una EFI interna por número de disco.
  4. Si se detiene por UUID distinto, falta de espacio o copia no válida, conserva el error. No quites las comprobaciones para forzar otro destino.
  5. Reinicia por el mismo USB y prueba primero macOS. Después prueba Tahoe con Enter normal.

Si ningún macOS arranca

Intenta entrar al Windows Boot Manager interno desde el menú ASUS, sin pasar por el OpenCore dañado. Windows puede leer los archivos FAT32 de MATE. Otra posibilidad es usar otro Mac o un medio OpenCore independiente que ya sepas que arranca.

  1. Localiza la carpeta del kit en MATE y comprueba que conserva 01-EFI-Actual/EFI/BOOT/BOOTx64.efi y 01-EFI-Actual/EFI/OC/OpenCore.efi.
  2. Si vas a montar una partición desde Windows, identifica primero el dispositivo USB de 31 GB y su partición FAT32 de unos 209 MB. No uses mountvol /S como atajo: puede seleccionar la EFI interna de Windows.
  3. Si sabes usar DiskPart, limita la operación a list disk, seleccionar el USB confirmado con select disk N, revisar detail disk, list partition y detail partition, y asignar una letra libre a su EFI. No ejecutar clean, format, convert, delete, set id ni active. Si Windows no permite asignarla, detente y usa otro entorno; no cambies el tipo de partición.
  4. Respalda primero la carpeta EFI que tenga ese USB. Copia después la carpeta EFI del kit a la raíz de esa partición, conservando la estructura EFI/BOOT y EFI/OC. No copies la carpeta a una EFI del disco interno ni anides una segunda EFI dentro de la primera.
  5. Expulsa los USB de forma segura y prueba el de 31 GB desde el menú ASUS. La restauración desde Windows y una sustitución física del USB no se han ensayado en este proyecto; requieren comprobar el destino cuidadosamente.

Si el USB está físicamente averiado, copiar archivos no lo repara. Un USB nuevo tendrá otros UUID: deberá prepararse e identificarse expresamente. El restaurador portátil se negará a escribir en un dispositivo nuevo por su cuenta.

5. Último recurso: reinstalar Sequoia

Primero decide qué conservar. Volver al Sequoia existente no borra Tahoe. Reinstalar Sequoia sobre su propio volumen puede conservar datos; sustituir Tahoe por un sistema anterior mediante instalación limpia elimina el grupo de volúmenes que selecciones. Esta guía no autoriza a borrar el disco completo.

A. Reparar el Sequoia existente sin borrar su volumen

  1. Respalda los documentos de ambos sistemas fuera del disco interno. La copia de EFI y los registros de este kit no reemplazan ese respaldo.
  2. Arranca por el USB de 31 GB → OpenCore → Install macOS Sequoia. El instalador ya estaba en ese USB; no se recreó ni se ensayó una reinstalación durante la preparación del kit.
  3. Revisa en el instalador qué versión ofrece. No presupongas que el USB instala exactamente 15.7.7/24G720. Si ofrece otra compilación, los recursos de parches deben corresponder a esa compilación.
  4. Selecciona macOS, el volumen de sistema de Sequoia. No elijas su volumen - Data, Tahoe ni Windows. No borres el volumen para una reinstalación de reparación.
  5. Conserva el USB conectado durante los reinicios. Elige «macOS Installer» si aparece para continuar la instalación y, al finalizar, «macOS».
  6. La reinstalación puede retirar parches de la GPU. El paquete OpenCore-Patcher-2.5.1-Sequoia.pkg está incluido como referencia de la versión usada en Sequoia. Instálalo únicamente dentro de Sequoia; no reconstruyas ni instales OpenCore en la EFI interna.
  7. Revisa «Post-Install Root Patch» antes de aplicar: debe detectar la GPU Kepler y disponer de los recursos de la compilación recién instalada. En un Hackintosh con Intel, la detección automática de Wi-Fi puede requerir evaluación aparte; no falsifiques la tarjeta como Broadcom para forzar parches.
  8. El kit conserva los recursos Metallib de 15.7.7/24G720. No deben usarse sobre otra compilación. La recuperación de gráficos/red después de una reinstalación limpia no se ha ensayado y no es una restauración automática de este kit.

B. Sustituir Tahoe por Sequoia mediante instalación limpia

  1. Usa esta vía solo si decides retirar Tahoe y ya tienes otra copia de sus archivos. No es una actualización hacia atrás que conserve automáticamente sus programas.
  2. Arranca el instalador de Sequoia por OpenCore. Abre Utilidad de Discos y activa «Mostrar todos los dispositivos».
  3. Identifica solo el grupo Tahoe-Pruebas / Tahoe-Pruebas - Data usando los nombres y UUID del inventario privado. El disco interno de 500 GB contiene también Windows y el Sequoia de recuperación.
  4. Si decides hacer una instalación limpia, el borrado debe limitarse a ese grupo de Tahoe. No seleccionar el disco físico, el contenedor APFS, la EFI, Windows ni el grupo macOS de Sequoia. Si no puedes distinguirlos, detente antes de borrar.
  5. Instala Sequoia en el destino limpio elegido, con un nombre inequívoco como «Sequoia-Rescate». Revisa sus parches con el mismo cuidado descrito arriba.
  6. Después de recrear volúmenes cambian sus UUID. Los comandos offline archivados para el antiguo Tahoe deben negarse a actuar: no edites sus UUID a ciegas para reutilizarlos.

El instalador de Sequoia y el perfil probado son específicos de este hardware. Una GPU diferente, una placa nueva o una actualización mayor necesitan su propia revisión.

Leer los registros divididos

Debes conservar todas las partes Registros-completos.tar.gz.part-* en la misma carpeta. Desde macOS se pueden listar sin extraer:

cat Registros-completos.tar.gz.part-* | tar -tzf -

Para extraerlos, elige una carpeta vacía en un disco con suficiente espacio, entra en ella y usa la ruta completa de las partes:

cat "/ruta/04-Registros-y-Respaldos/"Registros-completos.tar.gz.part-* | tar -xzf -

No extraigas el histórico encima de / ni de los registros activos. Sus scripts conservan rutas de la instalación original; muchos no son portátiles. El instalador de Tahoe de más de 18 GB y las extracciones duplicadas están excluidos del archivo para MATE. Sus metadatos y hashes se conservan; la descarga original sigue en el disco interno. Este kit no contiene un instalador completo de Tahoe ni copias de todos tus documentos.

Recuperar el repositorio sin GitHub

git clone Proyecto-OpenCore.bundle OpenCore-Legacy-Patcher
cd OpenCore-Legacy-Patcher
git switch main

El bundle contiene código e historial, no el intérprete Python ni todas las dependencias instaladas. Consulta SOURCE.md antes de recompilar. Las guías HTML y TXT se pueden leer sin Python, Git ni Internet.

7. Acciones que no deben convertirse en pruebas al azar

  • No borrar ni reemplazar la EFI interna de Windows para reparar macOS.
  • No usar comandos eraseDisk, clean, ni borrar el contenedor APFS completo.
  • No resetear NVRAM ni cambiar BIOS, SMBIOS, SIP o argumentos sin una causa concreta y un respaldo.
  • No aplicar desde Sequoia el comando habitual --patch_sys_vol esperando que seleccione Tahoe: apunta al sistema arrancado.
  • No reutilizar la caché offline de 25G241 sobre una actualización distinta.
  • No instalar OCLP 3 RC3 ni repetir root patches en el Sequoia de recuperación solo por ser una versión más nueva.
  • No desactivar XProtect por aparecer activo. Investigar consumo sostenido o alertas concretas por separado.
Punto de referencia probado: Tahoe 26.7.1/25G241, GT 730 GK208B de 2 GB, Intel AX201 y Realtek ALC897. El propietario informó Wi-Fi nativo funcional, unas dos horas de audio y ausencia de retrasos perceptibles. Es una prueba de uso satisfactoria, no una certificación de estabilidad indefinida ni de todas las funciones del hardware.
